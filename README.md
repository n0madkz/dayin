# Dayin

Cloudflare: https://dayin.aidin99mail-ru.workers.dev. Полная облачная версия использует Workers и постоянную SQLite-базу Durable Object; локальная база не переносится. Нижняя навигация видна только на мобильном экране, на ПК используется левое меню.

Команды Cloudflare: `npm run cloudflare:dev`, `npm run cloudflare:check`, `npm run cloudflare:deploy`. При первой настройке выполните `node cloudflare/create-secrets.cjs`, затем `npx wrangler login`, `npx wrangler secret bulk .runtime/cloudflare-secrets.json` и deploy. Не меняйте PASSWORD_PEPPER после создания учётных записей. Первоначальный доступ сохранён в `.runtime/cloudflare-access.md` и исключён из Git. В облаке обязательна смена временного пароля; `/dev/mail` отключён. Для регистрации новых владельцев с отправкой писем нужны секрет RESEND_API_KEY и настройка MAIL_FROM с подтверждённым доменом. Отложенное удаление выполняется через Durable Object alarm и при запросах.

Локальная платформа: каталог, меню, доставка, самовывоз, брони, кабинет владельца и админка. Нужен Node.js 24+. Перед первым запуском выполните npm ci.

Запуск: npm run start:local

Каталог: http://127.0.0.1:4173/
Локальная почта: http://127.0.0.1:4173/dev/mail

Один ресторан: Зелёный двор. Пример зарегистрированного владельца: Сәрсенов Айдос Нұрланұлы, aidos@dayin.test. Администратор: admin@dayin.test. Случайные временные пароли и ссылки на кабинеты находятся в локальных письмах. На настоящую почту в локальном режиме ничего не отправляется.

Регистрация: ФИО, почта, название заведения. Письмо содержит логин (почту), временный пароль и ссылку /account. Первый вход открывает только форму нового пароля и повторения. После смены временный пароль перестаёт работать. Он действует 24 часа. /admin требует роль администратора. Публичные переключатели кабинетов удалены.

Данные находятся в SQLite .runtime/dayin.sqlite. Пароли хешируются scrypt с индивидуальной солью. Сессии: HttpOnly SameSite cookies; токены хешируются на сервере. Проверяются права на ресторан, Origin и частота запросов. История гостя привязана к отдельной HttpOnly cookie.

Настоящая почта: адаптер Resend согласно https://resend.com/docs/api-reference/emails/send-email. Нужны RESEND_API_KEY, MAIL_FROM (подтверждённый домен), APP_URL (HTTPS), OWNER_EMAIL, OWNER_NAME, ADMIN_EMAIL, ADMIN_NAME. Ключи храните в окружении, не в исходниках и не в чате. Запуск: npm start. Для первого внешнего запуска задайте отдельный DATA_DIR, чтобы не переносить примерные .test аккаунты. Нужен HTTPS reverse proxy на локальный Node-сервер; Host и Origin должны совпадать с APP_URL. Локальная почта недоступна в режиме реальной отправки. Ответ Resend означает приём письма сервисом, а не подтверждение доставки. При ошибке отправки учётная запись не активируется и интерфейс сообщает об ошибке.

Проверки: npm test. Тестируются регистрация, принудительная смена пароля, изоляция ресторанов и гостей, расчёт цены на сервере, сохранение данных после перезапуска, отказ почтового сервиса, публичная навигация и декодирование SVG/PNG QR-кодов.

QR меню: в кабинете владельца откройте вкладку «QR меню», нажмите «Сгенерировать QR-код», затем скачайте SVG или PNG. Размеры PNG: 512, 1024 и 2048 px. Код ведёт на постоянную публичную страницу /menu/<restaurant-id>; обновления меню не меняют ссылку. Генерация происходит на сервере без отправки адреса стороннему QR-сервису. SVG пригоден для масштабирования, PNG экспортируется с белым фоном. В локальном режиме QR содержит loopback-ссылку: с телефона она не откроется. После публикации на публичном домене QR нужно сгенерировать заново.

Количество гостей: «Настройки заведения» → «Максимум гостей в одной брони». Допустимо целое число от 1 до 100; по умолчанию 8. Перед открытием формы бронирования загружаются актуальные настройки. Список гостей содержит только значения от 1 до лимита этого ресторана. Сервер проверяет текущий лимит при отправке, в том числе если владелец изменил его после открытия формы. Настройка сохраняется в базе; существующие заявки не меняются.

Халал: в настройках заведения укажите орган сертификации, номер, срок действия и HTTPS-ссылку на сертификат. После сохранения статус «На проверке». Администратор вручную проверяет документ и подтверждает или отклоняет его в колонке «Халал» в админке. Подтверждённый действующий сертификат даёт зелёную отметку «Халал» с галочкой в карточке и на странице меню. Нажатие на отметку открывает сведения и ссылку на документ. Изменение сертификата возвращает статус «На проверке»; при истечении срока, отклонении или удалении галочка не отображается. Отметка не ставится существующему примеру автоматически. Проверки сертификата во внешнем реестре и загрузки файлов пока нет.

Это локальная версия для проверки. Онлайн-платежи и ресторанные интеграции не подключены. Бронь является заявкой, подтверждаемой рестораном; проверки вместимости пока нет. До внешнего запуска нужны восстановление доступа, подтверждение владения заведением, аудит, резервные копии и настройка почтового домена. Старый статический Sites-манифест не подходит для текущего Node/SQLite сервера; публикация не выполнялась.

Клиенты: вход, регистрация и личный кабинет полностью отключены. Внизу доступны «Еда» и «Корзина». Заказ и бронирование доступны без аккаунта. Корзина сохраняется в браузере; гостевые заявки доступны только в этом браузере.

Фильтры каталога: выбор вида кухни и переключатель «Халал» работают совместно с поиском и избранным. Халал-фильтр показывает только заведения с подтверждённым сертификатом, срок которого не истёк. Есть сброс фильтров и пояснение при пустом результате. Вид кухни задаётся в настройках заведения; каталог и сервер используют общий перечень кухни из API.

Будущая регистрация клиента: номер телефона и код подтверждения через WhatsApp. Контракт в future/customer-auth.cjs отключён (enabled: false). Провайдер WhatsApp не подключён, сообщения не отправляются.

Клиентские страницы и API возвращают 404, прежние клиентские сессии не принимаются. Кабинеты владельца и администратора работают через ссылки из письма.


Заведения поддерживают несколько кухонь. Фильтры каталога объединяют выбранные кухни по принципу «любая из выбранных». Администратор переключает статус active/inactive; отключённое заведение не видно в каталоге и оно не принимает новые заявки. Удаление подтверждается текущим паролем администратора и назначается через 7 суток; до срока его можно отменить. Заведение сразу становится неактивным. По истечении срока удаляются заведение, меню, заявки, учётные записи владельцев и их сессии/локальные письма. Проверка срока выполняется раз в минуту, при запросах и при запуске сервера. Если сервер выключен, удаление выполняется после запуска.


Обновление для 1000 заведений: каталог выдаётся по 24 записи (максимум 48), меню загружается при открытии. Поиск и фильтры работают по всей базе; владельцу доступно только своё заведение. Облачные заказы и бронирования сохраняются в отдельном SQLite Durable Object каждого ресторана, с устойчивой очередью повторной записи в общий индекс для админки и истории. Существующие записи и аккаунты сохраняются. Публичные каталог и меню кешируются на 20 секунд, а при заказе статус и цены проверяются заново. Админка и история показывают последние 100 заявок.

Город — Атырау. Язык по умолчанию — казахский; верхний переключатель ҚАЗ / РУС / ENG сохраняет выбор, а ползунок анимируется без сброса заполненных форм. Данные ресторанов, названия блюд и описания, введённые владельцем, не переводятся автоматически. Палитра: глубокий зелёный, коралловый и белый.

Локальный нагрузочный тест Cloudflare на изолированной базе из 1000 заведений: 1000 запросов каталога/меню при concurrency 40 и 200 заказов при concurrency 20 — без ошибок. Чтение: 54.1 запроса/с, p95 1401 мс; запись: 19.6 запроса/с, p95 1792 мс. Это результаты локального workerd, а не предел мощности или гарантия для продакшена. Общий индекс и учётные записи остаются в центральном объекте; перед массовым запуском нужен тест фактического профиля трафика и настройка восстановления/резервирования. Тестовые заведения не публикуются. Повторение: отдельный persist-dir .runtime/cloudflare-local-scale, node cloudflare/seed-load-fixture.cjs, node cloudflare/load-test.cjs http://127.0.0.1:8788.
